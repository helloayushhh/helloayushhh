## 03 / how i build

i've been deliberately moving from **"make it work"** toward **"understand it, design it, build it, explain it."**

```text
        PROBLEM
           ↓
      DISCOVERY
           ↓
   BRD / REQUIREMENTS
           ↓
       PRD / UX
           ↓
       TRD / SYSTEM
           ↓
       BUILD / TEST
           ↓
    DATA / FEEDBACK
           ↓
      ITERATE / SHIP
           ↓
      DOCUMENT THE
        JOURNEY
```

### the principle

**code is one part of the product.**

i care about the reasoning around it too:

- what problem are we solving?
- who is it for?
- what should the product actually do?
- what trade-offs are being made?
- how does the system work?
- what does the data tell us?
- what changed between version 1 and version 2?

for selected projects, that thinking lives inside the repository through **brd, prd, trd, and project journey documentation**.
